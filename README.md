# mart-flyer-alert

동네 마트의 새 전단을 매일 확인해서, 미리 정한 기준보다 싼 품목과 1+1 행사만 텔레그램으로 보냅니다.

| 매장 | 전단 출처 |
|---|---|
| 이마트 평촌점 | [이마트 평촌점 카카오톡 채널](https://pf.kakao.com/_ZNRxnxj/posts)을 먼저 보고, 빠지는 주는 전국 공통 전단을 올리는 지점 채널로 메움: [월배점](https://pf.kakao.com/_ExjSJG/posts), [천안터미널점](https://pf.kakao.com/_xdGQxls/posts)(천안 지역판), [원주점](https://pf.kakao.com/_muxdcxj/posts), [울산점](https://pf.kakao.com/_avxcxob/posts) |
| 롯데마트 의왕점 | 롯데마트 전국 공통 전단: 지점 카카오톡 채널 세 곳을 함께 봄. [강변점](https://pf.kakao.com/_lBCxiK/posts), [그랑그로서리 은평점](https://pf.kakao.com/_wxiuXn/posts), [영종도점](https://pf.kakao.com/_xoKxfBK/posts) |
| 킴스클럽 평촌점 | [킴스클럽 카카오톡 채널](https://pf.kakao.com/_SBXxmxd/posts) (평촌점이 빠진 'N개점' 행사, 미리보기 글, 다른 지점 단독 글은 제외) |
| 홈플러스 평촌점 | 꺼 둠: 마트몬이 GitHub 서버 요청을 막고, 전단을 매주 올리는 카카오톡 채널을 찾지 못했다 |

처음에는 [마트몬](https://martmonster.com)에서 받았지만, 마트몬이 GitHub Actions 서버의 요청을 403 으로 거절해서 카카오톡 채널로 바꿨습니다.

### 어떤 게시물을 전단으로 보는가

규칙은 `config/stores.json`(`_comment` 에 설명)과 `scripts/fetch_flyers.py` 의 `kakao_candidate()`·`select_kakao_posts()` 에 있습니다.

- **출처**: 이마트는 평촌점 채널이 최근 1년 52주 가운데 약 38주 전단을 올렸습니다(2026-11-22 조사). 빠지는 주는 전국 공통 전단을 올리는 지점 채널로 메웁니다. 지점마다 올리는 주가 달라 네 곳을 함께 봅니다. 천안터미널점은 천안 3개 점포 전용 면이 붙은 천안 지역판을 올려서, 판독할 때 천안 지역 전용 품목은 빼고 옮깁니다. 롯데마트 의왕점 채널은 찾지 못해 지점 채널 세 곳(모두 매주 올림)을 봅니다.
- **정기 전단**: 제목이나 본문에 '전단'(이마트는 '이번 주 이마트 행사'도)이 있고 사진이 3장 이상인 글입니다. 이마트 평촌점 채널은 두 쪽을 펼친 사진을 올려서 2장부터 인정합니다.
- **행사 전단**: 고래잇·쓱데이·랜더스·랜쇼페·극한감사(이마트), 통큰데이·메가통큰(롯데마트)이 있는 글은 '전단' 낱말이 없거나 사진이 2장뿐이어도 인정합니다. 다만 이렇게 인정하는 글은 제목에 증정·스탬프·쿠폰·사은·경품·받아가·받으세요·챙겨가·모으고가 있으면 사은품 홍보 글로 보고 뺍니다.
- **행사 이름이 바뀔 때**: 행사 이름 목록은 미래에 낡을 수 있습니다. 그래서 목요일 17시가 지나도 그 주 전단을 못 찾으면, 전단 조건에 아깝게 못 미친 글(기간이 적혀 있고 사진 2장 이상이며, 제외 낱말·다른 지점 단독·사은품 제목이 아닌 글)을 Claude 가 사진까지 읽어 보고 전단이면 보냅니다(`fallback`). 이렇게 찾은 전단에는 "행사 낱말 목록에 없던 글이라 늦게 찾았습니다"가 붙습니다. 끝내 못 찾으면 금요일 17시 미발견 안내에 건너뛴 글의 제목과 링크를 적습니다. 새 행사 이름은 `event_any` 에 넣으면 다음부터 바로 잡힙니다.
- **제외**: 제목(제목 칸이 비면 본문 첫 줄)만 봅니다. 이마트 '광고상품', 킴스클럽 '미리보기'·'D-3' 같은 글, 그리고 다른 지점의 '단독' 글입니다. 평촌점·의왕점 채널의 글이거나 제목에 우리 매장 이름이 있는 단독 글은 빼지 않고, 그 주 전국 공통 전단과 따로 먼저 읽습니다.
- **같은 주**: 시작일이 같으면 한 번만 처리합니다. 우리 매장 채널 글 → 쪽수가 많은 글 → 전국판 순으로 고릅니다(펼친 사진은 두 쪽으로 셈). 이미 처리한 주라도 쪽수가 두 배 이상이고 세 쪽 이상 많은 전단이 새로 오면 한 번 더 읽어 보냅니다.
- **고쳐 올린 게시물**: 처리한 게시물의 제목과 사진 목록을 기억해 두고, 바뀌면 다시 읽습니다.
- **전단이 아닌 글**: Claude 가 읽어 보니 상품 가격이 없는 사은품 안내 같은 글이면 알리지 않고, 그 주 전단을 계속 기다립니다.
- **로그인 글**: 킴스클럽이 로그인해야 볼 수 있는 글로 전단을 올리면(2025년 가을부터 2026년 봄까지 그랬음) 사진을 읽을 수 없으니 "직접 확인해 주세요" 안내를 글마다 한 번 보냅니다(`state/restricted.json`).

이마트 공식 전단 페이지(eapp.emart.com, store.emart.com)는 `robots.txt` 가 자동 수집을 막고 있어서 쓰지 않습니다.

## 동작

`.github/workflows/flyers.yml` 이 매일 07:43, 17:43(KST)에 돕니다. 처음에는 08:30·18:30 이었는데, 정각·30분은 예약 실행이 몰려 4~9시간씩 늦게 시작해서 옮겼습니다.

1. `scripts/fetch_flyers.py` 가 매장의 채널마다 최근 게시물을 읽고, 아직 처리하지 않은 전단 게시물이 있으면 이미지를 내려받아 나눕니다(작은 글씨를 줄이지 않고 읽게 하려는 것입니다).
2. 새 전단이 있을 때만 Claude 가 이미지를 읽고 품목·규격·가격·조건을 JSON 으로 옮겨 적습니다(`prompts/extract.md`, `prompts/schema.json`). 구독 토큰으로 돌기 때문에 API 요금은 들지 않고, 쓰는 양은 구독 사용 한도에서 빠집니다. Claude 에게는 Read 도구 하나만 줍니다. 전단마다 Claude 세션을 따로 열고(조각이 30개를 넘는 전단은 두 세션에 나눔), 한 번 실행에 세션은 5개까지 씁니다. 한 세션에서 이미지를 너무 많이 읽으면 먼저 읽은 이미지가 대화에서 비워져 그 전단을 읽지 못하기 때문입니다.
3. `scripts/evaluate.py` 가 `config/criteria.json` 기준으로 판정하고 메시지를 만듭니다. 옮겨 적은 품목은 모두 `state/history/` 에 남깁니다.
4. `cards/render.py` 가 판정 결과로 1080x1350(4:5) 카드 이미지를 만듭니다. 요약(⭐ 품목은 가격표 모양), 나머지 품목과 1+1 목록, ⭐ 품목이 실린 전단 원본 조각 순서이고, 내용이 많으면 다음 장으로 이어집니다. 헤드리스 크롬으로 HTML 템플릿(`cards/templates/`)을 찍고, 글꼴은 저장소에 넣은 Pretendard(SIL OFL 1.1, `cards/fonts/LICENSE.txt`)를 씁니다.
5. `scripts/notify_telegram.py` 가 매장마다 앨범(2~10장, 첫 장에 ⭐ 품목을 적은 설명 글)을 먼저 보내고, 이어서 지금까지와 같은 텍스트 메시지를 보냅니다. 카드를 만들지 못하거나 앨범을 보내지 못해도 텍스트는 갑니다. 기준에 맞는 품목이 없어도 "새 전단이 올라왔다"는 짧은 메시지는 갑니다.
6. 목요일 17시 이후 첫 실행부터 그 주 일요일까지 한 번, 세 매장의 같은 품목을 단위 가격으로 맞춘 **매장 비교 카드**를 보냅니다(`config/compare.json`, 보낸 주는 `state/compare.json`). 두 매장 이상 전단에 나온 품목만, 관심 순서대로 최대 8개를 씁니다. 매장마다 최근 8일 안에 처리한 전단 가운데 행사 기간이 끝나지 않은 가장 최근 전단을 씁니다.

7. `scripts/check_missing.py` 는 금요일 17시가 지났는데도 이번 주 이마트·롯데마트 전단을 어느 채널에서도 찾지 못했으면 "이번 주 전단을 찾지 못했습니다" 안내를 보냅니다(`missing_alert`, 보낸 주는 `state/missing.json`). 그 주 일요일까지 매 실행이 확인하고, 매장마다 한 주에 한 번만 보냅니다. 사은품 안내처럼 전단이 아니었던 글은 '찾았다'로 치지 않고, 전단 조건에 아깝게 못 미친 이번 주 글이 있으면 안내에 제목과 링크를 적습니다.

카드 이미지는 실행마다 Actions 의 `cards` 아티팩트로 7일 동안 남습니다.

Claude 단계가 실패하거나 조각의 절반 이상을 읽지 못하면, 그 전단은 처리 표시를 하지 않아 다음 실행이 다시 읽습니다. 같은 전단을 두 번 실패하면 "직접 확인해 주세요" 메시지를 보내고 넘어갑니다.

## 설정

저장소 Settings → Secrets and variables → Actions 에 세 값을 넣습니다(RRG 저장소와 같은 값).

- `CLAUDE_SETUP_TOKEN`: 컴퓨터에서 `claude setup-token` 을 실행해 만든 구독 토큰
- `TELEGRAM_BOT_TOKEN`: @BotFather 에서 받은 봇 토큰
- `TELEGRAM_CHAT_ID`: 메시지를 받을 대화 ID

선택: Variables 탭에 `CLAUDE_MODEL`(기본 `claude-opus-5-5`)이나 `CLAUDE_EFFORT`(기본 `xhigh`, low·medium·high·xhigh·max 가운데 하나)를 두면 판독 모델이나 추론 강도를 바꿉니다.

## 수동 실행

Actions → flyers → Run workflow

- `force`: 이미 처리한 전단도 다시 읽을 매장 id(`emart_pyeongchon`, `lotte_uiwang`, `kims_pyeongchon`, 쉼표로 구분) 또는 `all`
- `dry_run`: 텔레그램으로 보내지 않고 실행 요약(Summary)에만 메시지를 남깁니다. 처리 표시도 하지 않습니다
- `compare`: 요일과 이번 주 발송 여부에 상관없이 매장 비교 카드를 만들어 보냅니다

## 기준 바꾸기

`config/criteria.json` 의 규칙은 위에서부터 차례로 맞춰 보고, 처음 맞는 규칙 하나로만 판정합니다.

- `basis`: `100g` · `kg` · `count`(개수당, `count_units` 로 단위 제한). `ok` 이하이면 알림, `great` 이하이면 ⭐
- `min_pct` / `great_pct`: 할인율 기준. `basis` 기준과 함께 있으면 둘 중 하나만 맞아도 알림
- `origin`: `domestic`(국내산·한우·한돈) · `import`(수입)
- `no_seasoned`: 양념육·훈제·가공품 제외(양념 무게 때문에 100g당 가격이 싸 보이는 것을 막습니다)
- 1+1 은 절반, 2+1 은 3분의 2 가격으로 계산합니다
- 1+1 묶음 알림 대상은 `bogo` 항목(냉장·냉동 식품, 신선식품, 생필품)입니다

기준가는 2026-11 KAMIS·축산물품질평가원 소매가격보다 약 20~30% 싼 수준으로 잡았습니다. `state/history/` 에 쌓인 실제 전단 가격을 보고 다시 조정하면 됩니다.

## 매장 추가

`config/stores.json` 에 추가합니다. 카카오톡 채널은 `source: kakao` 와 `channels`(채널 id `pf.kakao.com/_xxxx` 의 `_xxxx` 와 이름)를 적습니다. 우리 매장 채널이면 `own: true`, 지역판을 올리는 채널이면 `regional: true` 를 붙입니다. 채널이 하나면 예전처럼 `channel`·`channel_name` 만 적어도 됩니다. 마트몬(`source: martmonster`) 수집 코드도 남아 있지만, GitHub 서버에서는 403 으로 막힙니다.

## 시험

```bash
pip install pillow jinja2 playwright
python -m unittest discover -s tests -v
```

카드를 직접 찍어 보려면 Chrome 이 있는 컴퓨터에서 `work/cards.json` 을 만든 뒤 `python cards/render.py` 를 실행합니다.
